# Build a Production-Ready AI Job Hunting Agent — Full-Stack Project

Act as a senior AI engineer, full-stack developer, software architect, database engineer, and automation specialist. Your task is to **build a working AI Job Hunting Agent**, not merely explain how to build one or generate a design document.

Work directly in the current repository using the available CLI tools. Inspect existing files before making changes. If the repository is empty, initialize the project. Create actual source files, database migrations, tests, documentation, and configuration. Implement the project incrementally, run tests, fix errors, and keep the application runnable.

## 1. Product Objective

Build a personal AI Job Hunting Agent that discovers relevant job opportunities, evaluates them against my professional profile, chooses the correct regional resume, finds legitimate application contacts, prepares personalized applications, sends approved email applications automatically, tracks their status, and generates daily reports.

The system should include:
- Full-stack web dashboard.
- Python backend and AI workflow.
- Regional job discovery and prioritization.
- Four independent regional resumes.
- Job matching and eligibility checks.
- Verified recruiter contact discovery.
- Personalized email generation.
- Gmail integration using OAuth 2.0.
- Browser automation for supported websites and permitted application workflows.
- Application tracking, retries, deduplication, daily quota management, logging, and notifications.

Do not stop after generating a plan. Implement the working MVP, validate it, and report any incomplete integrations honestly.

- Pakistan job → Pakistan CV.

- Store the file in private object storage or an equivalent private storage implementation.
- Record its region, version, checksum, upload time, and active status.
- Prevent public access to resume files.
- Confirm the selected resume exists and belongs to the current user before applying.
- If the correct resume is missing, pause that application and request user intervention.

Do not invent my personal details, degrees, experience, employment history, or achievements. Use only information from my approved profile and resume. Allow resume replacement and version history.

## 9. Automatic Sending and Safety Gates

Email mode should be automatic once the user has connected Gmail, configured the resume, approved the template, and enabled sending.

Before every send, validate:
1. The job is still eligible.
2. It satisfies the 72-hour freshness rule, or an explicitly configured exception applies.
3. The job matches the configured score threshold.
4. The recipient is legitimate and meets the configured verification policy.
5. The correct regional resume is active and accessible.
6. The email is based on verified job information and approved user facts.
7. No duplicate application exists.
8. The global daily cap has capacity.
9. The global pause switch is off.
10. No policy or contact exclusion prevents sending.

Implement a transactional daily quota reservation. Multiple workers must not be able to exceed the global limit of 30.

Use an idempotency key and a reconciliation mechanism to handle crashes and retries. Never blindly resend if the previous request may already have been accepted by Gmail.

Keep these states distinct:
- `queued`
- `preparing`
- `ready`
- `sent`
- `submitted`
- `delivery_confirmed`
- `bounced`
- `replied`
- `failed`
- `needs_manual_action`
- `skipped`
- `cancelled`

Only use `sent` after a successful provider response. Only use `delivery_confirmed` when a reliable delivery signal supports it. Email replies should be tracked only through an explicitly configured, authorized integration.

### Browser-based applications

Implement browser application automation as a separate, modular capability. Do not mix portal submission logic with the email sender.

Initially:
- Collect job listings.
- Open official application URLs.
- Provide supported form-filling and resume-upload workflows only where permitted.
- Stop when CAPTCHA, MFA, unexpected consent, or an unsupported workflow requires manual intervention.
- Do not automatically submit a portal application until that particular workflow has been tested and explicitly enabled in configuration.

## 11. Workflow Orchestration

Implement this workflow with persisted progress and retry-safe stages:

1. Load user configuration.
2. Load enabled regions sorted by priority.
3. Discover jobs from configured, permitted sources.
4. Normalize listing data.
5. Deduplicate listings.
6. Check posting age.
7. Evaluate match score and hard eligibility.
8. Save the score and explanation.
9. Discover and validate application contacts.
10. Select the regional resume.
11. Generate a personalized email.
12. Run all safety checks.
13. Reserve daily quota transactionally.
14. Send via Gmail API.
15. Record provider response and application events.
16. Handle failures without duplicate sends.
17. Continue to the next eligible job while quota remains.
18. Generate and email the daily summary.

If one source fails, continue with other configured sources. Persist errors and retry according to bounded exponential backoff. Do not retry permanent failures indefinitely.

The workflow should be restartable after a crash without repeating completed steps.
